Camera / CameraAction / LockOn / Collision 説明メモ

最終編集日時
7/21

目的
このメモは、現在のカメラまわりの構成と、ジャスト回避・ジャストガードなどの短時間演出を EventSystem から呼び出せるようにした部分を説明するためのもの。
単に「カメラを動かす」ではなく、TPS、ロックオン、壁際補正、衝突補正、FOV、イベント演出が同じフレームで競合しないように、役割を分けている。


============================================================
1. 全体概要
============================================================

このプロジェクトの通常カメラは、主に次のコンポーネントで構成している。

- CameraManager
- CameraComponent

- ThirdPersonCameraComponent
- CameraLockOnComponent
- CameraCollisionComponent
- CameraDirector
- FovDirector
- CameraActionDirectorComponent
- CameraShakeComponent

CameraComponent は、最終的な eye / focus / up / FOV / view / projection を持つ基本コンポーネント。
ThirdPersonCameraComponent は通常のTPS追従を担当し、プレイヤーを中心に距離、ピッチ、ヨー、入力による視点変更を行う。
CameraLockOnComponent は、プレイヤーと敵を画面内に収めるロックオン構図を作る。
CameraCollisionComponent は、通常カメラやロックオンカメラの結果に対して、壁や障害物でカメラが埋まらないように最終位置を補正する。
CameraManager は、レンダリングで使用するアクティブカメラを選び、必要に応じてプロキシカメラへコピーする。
CameraDirector と FovDirector は、登録済みのウェイポイントやFOV演出を再生する既存の演出用コンポーネント。

CameraActionDirectorComponent は、通常カメラが出した姿勢に対して、戦闘中の短時間だけ割り込む一時演出レイヤーとして設計している。
ジャスト回避やジャストガードのような、0.1秒から0.4秒程度の「見せたい瞬間」だけ、カメラ位置、注視点、FOV、軽い揺れを補正する。

CameraShakeComponent は、構図変更を伴わないカメラ揺れ専用のコンポーネント。
CameraActionDirectorComponent でも簡易 shakeStrength は持っているが、純粋な衝撃表現だけを EventSystem から呼びたい場合は CameraShakeComponent を使う。


============================================================
2. 設計方針
============================================================

解決したかった問題は、通常カメラ制御と戦闘演出カメラ制御が同じ CameraComponent を同時に書き換えること。

通常カメラでは、TPS、ロックオン、カメラ衝突補正が毎フレーム CameraComponent に姿勢を書き込む。
そこへジャスト回避やジャストガードの演出をそのまま追加すると、次のような問題が起きる。

- TPS入力が演出中にも視点を動かしてしまう
- ロックオン構図が演出の注視点を上書きしてしまう
- CameraCollision が短い演出の位置を大きく崩してしまう
- FOV を複数コンポーネントが同時に SetFov して結果が読みにくくなる
- 演出終了時に通常カメラへ戻る向きが急に跳ねる

そのため、CameraActionDirectorComponent は演出再生中だけ次の制御を行う。

- 演出開始時のカメラ位置、注視点、FOVを保存
- 必要に応じて ThirdPersonCameraComponent の入力制御を一時停止
- 必要に応じて CameraLockOnComponent の制御を一時停止
- 必要に応じて CameraCollisionComponent の補正を一時停止
- ENTER / HOLD / RETURN の3段階で短時間演出を進行
- RETURNで通常カメラが計算する姿勢へ補間復帰
- 復帰時に ThirdPersonCameraComponent::SynchronizeViewAngles と BeginReturnBlendFromCurrentCamera を使い、TPS視点が急に跳ねないようにする

既存の CameraDirector は、登録済みの Transform / FOV ウェイポイントを再生する用途として残している。
今回の CameraActionDirectorComponent は、戦闘イベントから動的なヒット位置や対象を渡して再生する用途として分けている。


============================================================
3. 主なクラス
============================================================

CameraComponent
- 種類: Component
- 場所: Code/Engine/GamePlay/Camera/
- 主な役割:
  カメラの最終的な eye / focus / up / view / projection / FOV を保持する。
  SetLookAt と SetFov が、他のカメラ制御コンポーネントから呼ばれる基本APIになっている。
- 注意点:
  CameraComponent::LateUpdate は Transform から view を更新するため、TPS、ロックオン、衝突補正、演出側は LateUpdate 順を意識して最終姿勢を上書きする。

ThirdPersonCameraComponent
- 種類: Component
- 場所: Code/Engine/GamePlay/Camera/
- 主な役割:
  プレイヤーを追従するTPSカメラ。
  右スティックやマウス入力から yaw / pitch を更新し、プレイヤー中心のカメラ位置を計算する。
- 重要なAPI:
  SetControlSuppressed
  SynchronizeViewAngles
  BeginReturnBlendFromCurrentCamera
- 演出との関係:
  CameraActionDirectorComponent が演出中だけ SetControlSuppressed(true) を呼び、終了時に false に戻す。
  復帰時は SynchronizeViewAngles で現在のカメラ向きをTPS内部の yaw / pitch に反映し、BeginReturnBlendFromCurrentCamera で通常視点へ滑らかに戻す。

CameraLockOnComponent
- 種類: Component
- 場所: Code/Engine/GamePlay/Camera/
- 主な役割:
  プレイヤーとロックオン対象を画面内に収める構図を作る。
  距離、壁際、画面内安全領域、FOV補正などを見て CameraComponent に姿勢を書き込む。
- 追加したAPI:
  SetActionSuppressed
  IsActionSuppressed
- 演出との関係:
  ロックオン状態そのものは壊さず、演出中だけ LateUpdate の制御を止める。
  SetLockOnEnabled(false) とは違い、lockOnTarget や currentSide などのロックオン状態は維持する。

CameraCollisionComponent
- 種類: Component
- 場所: Code/Engine/GamePlay/Camera/
- 主な役割:
  focus から desired camera position までの間を Sweep し、壁や障害物にめり込まないようにカメラ位置を補正する。
  ロックオン中は CameraLockOnComponent の ApplyCollisionComposition と連携し、壁際でもプレイヤーと敵が画面に残るように補正する。
- 追加したAPI:
  SetCollisionSuppressed
  IsCollisionSuppressed
- 演出との関係:
  ジャストガードなどの短い演出では、衝突補正で構図が大きく崩れる場合がある。
  プリセットごとに suppressCameraCollision を設定し、必要な演出だけ衝突補正を止められる。

CameraManager
- 種類: Manager
- 場所: Code/Engine/GamePlay/Camera/
- 主な役割:
  シーン内の CameraComponent から priority の高いものを選び、レンダリング用の proxy camera にコピーする。
- 追加したAPI:
  GetSourceCamera
- 理由:
  GetActiveCamera はレンダリング用 proxy camera を返す。
  proxy camera には CameraActionDirectorComponent が付いていないため、ジャスト回避・ジャストガード側から「実カメラのGameObject」を探すために GetSourceCamera を追加した。

CameraActionDirectorComponent
- 種類: Component / IActionProvider
- 場所: Code/Engine/GamePlay/Camera/
- 主な役割:
  戦闘イベント用の短時間カメラ演出を再生する。
  EventSystem からは CameraAction / JustGuard、CameraAction / JustDodge のように呼び出せる。
- 主なAPI:
  PlayActionByIndex
  PlayActionByName
  PlayActionAtPosition
  PlayActionForTarget
  StopAction
- 再生フェーズ:
  IDLE
  ENTER
  HOLD
  RETURN
- 重要なデータ:
  CameraActionPreset
  actionName
  targetMode
  positionMode
  cameraOffset
  focusOffset
  enterDuration
  holdDuration
  returnDuration
  targetFov
  shakeStrength
  shakeFrequency
  priority
  suppressThirdPersonControl
  suppressLockOnControl
  suppressCameraCollision
  useUnscaledTime
  blackboardCategory
  focusPositionKey
  attackDirectionKey
- 注視点の決定:
  PlayActionAtPosition で渡された位置を最優先する。
  EventSystem から引数なしで呼ばれた場合は、プリセットの blackboardCategory / focusPositionKey / attackDirectionKey を使って BlackboardComponent から位置を読む。
  取得できない場合は、対象GameObject、プレイヤー、ロックオン対象、現在のCamera focus の順でフォールバックする。

CameraShakeComponent
- 種類: Component / IActionProvider
- 場所: Code/Engine/GamePlay/Camera/
- 主な役割:
  構図変更なしのカメラ揺れを再生する。
  EventSystem から CameraShake / Light、CameraShake / Heavy、CameraShake / JustGuard のように呼び出せる。
- 主なデータ:
  CameraShakePreset
  actionName
  duration
  positionStrength
  rotationStrength
  frequency
  fadeInRate
  fadeOutRate
  priority
  useUnscaledTime
- 実装方針:
  毎フレーム完全な乱数ではなく、複数の sin 波を使って安定した揺れを作る。
  priority が低い揺れは、再生中の高優先度揺れを上書きしない。


============================================================
4. CameraActionPreset の考え方
============================================================

CameraActionPreset は、1つの戦闘カメラ演出を表すデータ。

targetMode は、注視対象をどこから取るかを表す。

WORLD_POSITION
  固定ワールド座標を使う。

GAME_OBJECT
  指定された GameObject の位置を使う。

GAME_OBJECT_OFFSET
  GameObject の位置に offset を加えた位置を使う想定。

HIT_POSITION
  ジャストガードやヒット位置など、外部から渡された接触位置を使う。

PLAYER
  プレイヤー位置を使う。

LOCK_ON_TARGET
  現在のロックオン対象を使う。

positionMode は、カメラ位置をどの基準で解釈するかを表す。

CURRENT_CAMERA_RELATIVE
  現在カメラの right / up / front を基準に offset を加える。

TARGET_LOCAL_RELATIVE
  攻撃方向や接触法線を基準に、対象まわりの構図を作る。

PLAYER_FORWARD_RELATIVE
  プレイヤーの向きを基準に、ジャスト回避などの横回り構図を作る。

WORLD_POSITION
  cameraOffset 自体をワールド座標として使う。

JustGuard の初期プリセットでは、Guard ブラックボードの Position / Normal を使う。
JustDodge の初期プリセットでは、Dodge ブラックボードの Position / Normal を使う。


============================================================
5. ジャスト回避・ジャストガードとの連携
============================================================

JustDodgeSystem
- ジャスト回避成功時、Blackboard に Dodge / Position と Dodge / Normal を書く。
- 既存の OnJustDodge ローカル Action も呼ぶ。
- 今回、実カメラの CameraActionDirectorComponent を探して、PlayActionAtPosition("JustDodge", position, normal) を呼ぶ導線を追加した。

GuardSystem
- ガード成功時、Blackboard に Guard / Position と Guard / Normal を書く。
- 通常ガードでは OnGuardSucceeded を呼ぶ。
- ジャストガードでは OnJustGuardSucceeded を呼ぶ。
- 今回、ジャストガード時だけ PlayActionAtPosition("JustGuard", position, normal) を呼ぶ導線を追加した。

これにより、次の2つの使い方ができる。

1. システム側から動的な接触位置を直接渡す
  ジャスト回避・ジャストガードの実際の接触位置を使うので、演出の注視点が毎回変わる。

2. EventSystem から引数なし Action として呼ぶ
  CameraAction / JustGuard や CameraAction / JustDodge を登録済み Action として呼べる。
  この場合は、CameraActionPreset に設定された Blackboard の category / key から注視点を読む。


============================================================
6. EventSystem に登録される Action
============================================================

CameraActionDirectorComponent
- Category: CameraAction
- Action:
  JustGuard
  JustDodge
  追加した preset の actionName

CameraShakeComponent
- Category: CameraShake
- Action:
  Light
  Heavy
  JustGuard
  追加した preset の actionName

CameraLockOnComponent
- Category: Camera
- Action:

  LockOn_Disable
  LockOn_Toggle
  LockOn_SwitchSide

CameraDirector / FovDirector
- 既存通り、登録済みウェイポイントやFOV演出の再生に使う。


============================================================
7. 更新順と競合対策
============================================================

通常時の考え方
1. ThirdPersonCameraComponent がTPSカメラ姿勢を計算する
2. CameraLockOnComponent がロックオン中なら構図を上書きする
3. CameraCollisionComponent が壁や障害物に対して最終位置を補正する
4. CameraManager がレンダリング用 proxy camera へコピーする

CameraAction 再生中
1. 演出開始時にTPS / LockOn / Collision の必要な制御を一時停止する
2. CameraActionDirectorComponent が ENTER / HOLD / RETURN でカメラを上書きする
3. RETURN 開始時に一時停止を解除し、通常カメラが計算する復帰先へ補間する
4. TPSへ戻る場合は yaw / pitch を同期し、BeginReturnBlendFromCurrentCamera で急な跳ねを抑える

重要なのは、CameraAction が CameraManager のカメラ優先度を切り替えないこと。
新しい CameraComponent を生成したり、CameraManager の priority を頻繁に変えたりせず、現在の実カメラに対する一時補正として扱っている。


============================================================
8. JSON / Editor
============================================================

CameraActionDirectorComponent は presets を JSON に保存する。
保存対象は、actionName、targetMode、positionMode、cameraOffset、focusOffset、duration、FOV、shake、priority、各 suppress 設定、Blackboard key。

Gui では次を編集できる。
- preset 追加 / 削除
- actionName
- targetMode
- positionMode
- cameraOffset
- focusOffset
- enter / hold / return duration
- FOV
- shakeStrength / shakeFrequency
- priority
- TPS / LockOn / Collision の一時停止設定
- Blackboard category / key
- Capture Current Camera
- Play Preview
- Stop

CameraShakeComponent も presets を JSON に保存する。
Gui では duration、positionStrength、rotationStrength、frequency、fadeIn / fadeOut、priority を編集できる。


============================================================
9. 使い方
============================================================

ジャストガード成功時の直接呼び出し

cameraAction_->PlayActionAtPosition(
    "JustGuard",
    guardHitPosition_,
    attackDirection_);

ジャスト回避成功時の直接呼び出し

cameraAction_->PlayActionAtPosition(
    "JustDodge",
    dodgePosition_,
    attackDirection_);

EventSystem から呼ぶ場合

CameraAction / JustGuard
CameraAction / JustDodge
CameraShake / Light
CameraShake / Heavy
CameraShake / JustGuard

EventSystem から引数なしで呼ぶ場合は、先に対象の Blackboard に位置を入れておく。

Guard / Position
Guard / Normal
Dodge / Position
Dodge / Normal


============================================================
10. 注意点
============================================================

- CameraActionDirectorComponent は、演出用 CameraObject ではなく、通常使用している実カメラの GameObject に付ける。
- CameraManager::GetActiveCamera は proxy camera を返すため、コンポーネント検索には使わない。
- ジャスト系システムからは CameraManager::GetSourceCamera を使って実カメラを取る。
- suppressLockOnControl はロックオンそのものを解除しない。演出中だけ LateUpdate を止める。
- suppressCameraCollision はプリセットごとに使い分ける。壁際の演出が崩れる場合は true、壁抜けを避けたい場合は false。
- FOV は 10.0 から 120.0 に clamp する。
- priority が低い CameraAction は、再生中の高優先度 CameraAction を上書きしない。
- CameraShake は構図変更とは別に使えるが、CameraAction と同時に最終姿勢を書き込むため、強い shake を併用しすぎると見づらくなる。


============================================================
11. 今後の拡張候補
============================================================

- CameraActionPreset の GAME_OBJECT_OFFSET をより明確に実装する
- TimeManager の unscaled delta time を使って、useUnscaledTime を完全対応させる
- CameraAction と CameraShake の同時適用順を明示的に管理する
- CameraAction の DebugDraw を追加して、focus と camera target を Scene 上で見えるようにする
- EventSystem 側が引数付き Action に対応した場合、Blackboard 経由を減らして直接値を渡せるようにする
