目的
このメモは、キャラクターやドラゴンの骨制御、接地、注視、盾構え、首や尻尾の追従などを説明するための入口。
アニメーション再生だけでは表現しにくい、状況に応じたポーズ補正の仕組みとして整理する。

主な関連ファイル
- Code/Engine/Graphics/Resource/Animation/IKMapComponent.h / .cpp
- Code/Engine/Graphics/Resource/Animation/FootIKComponent.h / .cpp
- Code/Engine/Graphics/Resource/Animation/HumanLookAtIKComponent.h / .cpp
- Code/Engine/Graphics/Resource/Animation/ShieldBlockIKComponent.h / .cpp
- Code/Engine/Graphics/Resource/Animation/UpperBodyLeanIKComponent.h / .cpp
- Code/Engine/Graphics/Resource/Animation/DragonNeckCommandIKComponent.h / .cpp
- Code/Engine/Graphics/Resource/Animation/DragonTailCommandIKComponent.h / .cpp
- Code/Engine/Graphics/Resource/Animation/SpringBoneSimulationComponent.h / .cpp

この機能を一言で説明するなら
再生中のアニメーションに対して、接地、注視、防御姿勢、ドラゴンの首や尻尾などを状況に応じて補正する IK / Bone 制御システム。

説明の中心
- IKMapComponent が IK 用の骨情報や対象ノードを管理する
- FootIKComponent が足の接地補正を行う
- HumanLookAtIKComponent が頭や上半身の注視を行う
- ShieldBlockIKComponent が盾構えの補正に使われる
- UpperBodyLeanIKComponent が上半身の傾き補正に使われる
- DragonNeckCommandIKComponent / DragonTailCommandIKComponent がドラゴン用の特殊な骨制御を行う
- SpringBoneSimulationComponent が揺れもの表現に使われる

面接での短い説明
「IK 系の Component では、アニメーションだけでは合わせきれない足の接地や視線、盾の向き、ドラゴンの首や尻尾の動きを補正しています。
AnimationController の再生結果を元にしつつ、IKMapComponent で対象の骨を管理し、各 Component が目的に応じてボーン姿勢を調整する設計です。」

10. 良い点と改善点

良い点
- アニメーション素材だけに頼らず、ゲーム中の状況に合わせて姿勢を補正できる
- 人型用とドラゴン用で専用 Component を分けている
- IKMap により、骨名や対象ノードの扱いを共通化できる

改善点
- IK は順番や適用タイミングで結果が変わるため、更新順の説明を整理するとよい
- Bone 名の文字列参照は、モデル差し替え時に注意が必要
- Debug 表示で目標位置、補正量、対象ボーンを見えるようにすると調整しやすい


============================================================
1. IK 全体概要
============================================================

IK 関係の実装は、通常のアニメーション再生だけでは合わせきれない姿勢を、ゲーム中の状況に応じて補正するための仕組み。

アニメーションは基本の動きを表現するが、地面の高さ、ターゲットの位置、盾を向ける方向、ドラゴンの首や尻尾の向きなどは、ゲーム中に変わる。
そのため、AnimationController や ModelAnimator が作った姿勢に対して、各 IK Component が後から補正をかける。

このプロジェクトでは、人型用の FootIK、LookAtIK、ShieldBlockIK、UpperBodyLeanIK と、ドラゴン用の Neck / Tail IK、揺れもの用の SpringBone が分かれている。
IKMapComponent は、これらの IK が使う骨やノードの対応を管理する入口として説明できる。

一言で説明するなら、
「再生中のアニメーションに対して、足の接地、視線、盾構え、ドラゴンの首や尻尾、揺れものを状況に合わせて補正する Bone 制御システム」
と言える。


============================================================
2. この機能を作った理由
============================================================

解決したかった問題
- アニメーション素材だけでは、足が地面にめり込むことがある
- ターゲットの位置に合わせて顔や上半身を向けたい
- 盾を構える方向や上半身の傾きをゲーム中の状況に合わせたい
- ドラゴンの首や尻尾のように、長い骨チェーンを自然に動かしたい
- 髪、尻尾、装飾などの揺れを手付けアニメーションだけで作るのは大変

この設計で改善したこと
- 用途ごとに IK Component を分け、責務を小さくした
- IKMapComponent により、対象ボーンやノード情報をまとめる入口を作った
- 人型とドラゴン用の特殊処理を別 Component に分けた
- Animation の結果に対して後段で補正する形にした
- Editor / Serialize によって、対象ボーンや補正量を調整できる入口を作った


============================================================
3. 全体構成
============================================================

IKMapComponent
- 種類: Component
- 主な責務:
  IK で使う骨やノードの対応を管理する。
- 説明のポイント:
  各 IK Component が直接モデル構造をバラバラに探すのではなく、IKMap を通して対象を扱うための土台。

FootIKComponent
- 種類: Component
- 主な責務:
  足の接地補正。
- 説明のポイント:
  地面の高さに合わせて足位置や膝の向きを調整し、アニメーションだけでは起きる足の浮きやめり込みを軽減する。

HumanLookAtIKComponent
- 種類: Component
- 主な責務:
  人型キャラクターの視線、首、上半身の向き補正。
- 説明のポイント:
  ターゲットや注視点へ自然に向けるための補正。

ShieldBlockIKComponent
- 種類: Component
- 主な責務:
  盾構えの補正。
- 説明のポイント:
  防御中に盾を攻撃方向やターゲット方向へ向けるための Component として説明できる。

UpperBodyLeanIKComponent
- 種類: Component
- 主な責務:
  上半身の傾き補正。
- 説明のポイント:
  移動、攻撃、向き変更などに合わせて上半身を自然に傾ける。

DragonNeckCommandIKComponent
- 種類: Component
- 主な責務:
  ドラゴンの首の骨チェーン制御。
- 説明のポイント:
  長い首をターゲット方向へ向ける、攻撃予備動作に合わせるなど、通常の人型 IK では扱いにくい動きを専用化している。

DragonTailCommandIKComponent
- 種類: Component
- 主な責務:
  ドラゴンの尻尾の骨チェーン制御。
- 説明のポイント:
  体の動きや攻撃に合わせて、尻尾を自然に追従させる。

SpringBoneSimulationComponent
- 種類: Component
- 主な責務:
  揺れものの簡易シミュレーション。
- 説明のポイント:
  髪、装飾、尻尾の先などに、物理風の遅れや揺れを入れる。


============================================================
4. IK の基本的な処理フロー
============================================================

一般的な流れ
1. AnimationController / ModelAnimator が基本姿勢を作る
2. モデルのボーン行列やノード Transform が更新される
3. IKMapComponent が対象ボーンやノードを把握する
4. 各 IK Component が現在状況を読む
5. 目標位置や目標方向を計算する
6. 対象ボーンの回転や位置を補正する
7. 補正後の姿勢で RenderSystem が描画する

重要な考え方
- IK はアニメーションを置き換えるものではない
- まず基本アニメーションを再生し、その結果に補正を加える
- 適用順によって結果が変わるため、更新順の整理が重要
- やりすぎるとアニメーションの意図が壊れるため、補正量や重みが必要になる


============================================================
5. FootIK
============================================================

目的
- 足が地面に浮く、めり込む問題を軽減する
- 段差や地形に合わせて足を置く
- キャラクターの接地感を上げる

処理として説明できる流れ
1. 足ボーン、膝ボーン、腰などの対象を取得する
2. 足元方向へ Raycast する
3. 地面の高さと法線を取得する
4. 足先の目標位置を決める
5. 膝の向きや足首の回転を補正する
6. 必要なら腰の高さも調整する
7. 補正量を滑らかにしてガタつきを防ぐ

注意点
- Raycast が失敗した場合の fallback が必要
- 急な段差では補正量を制限しないと不自然になる
- 左右の足で補正タイミングがずれると姿勢が破綻しやすい


============================================================
6. LookAt / Shield / UpperBody
============================================================

HumanLookAtIK
- ターゲットや注視点の方向を計算する
- 首、頭、上半身へ回転を分配する
- 急に向きすぎないよう角度制限や補間を入れると自然になる

ShieldBlockIK
- 防御中の盾の向きを補正する
- 攻撃方向やロックオン対象へ盾を向ける
- 手、腕、肩の姿勢補正として説明できる

UpperBodyLeanIK
- 入力方向や速度、攻撃方向に合わせて上半身を傾ける
- 移動や攻撃の迫力を出す補正として説明できる

説明で大事な点
- すべてを手付けアニメーションで作るのではなく、ゲーム中の情報で補正している
- IK の重みを変えれば、通常時と戦闘時で補正の強さを変えられる
- 人型の見た目の自然さを上げるための後処理として説明できる


============================================================
7. Dragon IK
============================================================

DragonNeckCommandIK
- 長い首の複数ボーンを使って、頭をターゲット方向へ向ける
- ボスの視線、ブレス攻撃、噛みつき前の予備動作に使える
- 人型の LookAt よりもチェーンが長いため、専用 Component にしている

DragonTailCommandIK
- 尻尾の複数ボーンを制御する
- 体の向きや移動に遅れて追従させる
- 尻尾攻撃やバランス表現にも使える入口

設計上の説明
「ドラゴンは人型と骨構造も動きも違うため、汎用 LookAt だけではなく専用 Component として分けています。
これにより、人型キャラクターの IK を壊さずに、ボス専用の動きを追加できます。」


============================================================
8. SpringBone
============================================================

目的
- 髪、布、装飾、尻尾の先などに揺れを入れる
- 手付けアニメーションだけでは固く見える部分を柔らかくする

処理として説明できる流れ
1. 対象ボーンを取得する
2. 前フレーム位置と現在位置から揺れを計算する
3. 重力や慣性、減衰を加える
4. ボーン長や角度制限を守る
5. 結果をボーン姿勢へ反映する

注意点
- 揺れすぎると破綻するため、減衰や制限が必要
- フレームレート差で挙動が変わらないよう deltaTime を考慮する
- モデルごとにボーン名が違うため、設定を外部化すると扱いやすい


============================================================
9. Serialize / Editor
============================================================

保存したい項目
- 対象ボーン名
- ターゲット名
- 補正の重み
- 角度制限
- 補間速度
- Raycast 距離
- 地面オフセット
- Spring の強さ
- 減衰
- Debug 表示の有無

Editor で見たい項目
- IK の有効 / 無効
- 対象ボーン
- 目標位置
- 補正量
- 現在の Weight
- Raycast 結果
- FootIK の接地点
- LookAt の注視方向
- SpringBone の揺れ状態

説明のポイント
「IK は見た目の調整が重要なので、コードだけで完結させず、Editor から対象ボーンや補正量を確認できるようにするのが大事です。」


============================================================
10. 想定質問と回答例
============================================================

質問: IK はなぜ必要ですか？
回答:
アニメーション素材だけでは、地形やターゲット位置のようにゲーム中に変わる状況へ完全には対応できないからです。
IK を使うことで、足の接地や視線、盾の向きなどを実行時に補正できます。

質問: IKMapComponent の役割は？
回答:
各 IK Component が使う骨やノード情報を管理する入口です。
IK ごとにモデル内のボーンをバラバラに探すのではなく、共通のマップを使うことで扱いやすくしています。

質問: 人型 IK とドラゴン IK を分けた理由は？
回答:
骨構造と必要な動きが違うためです。
人型は足、視線、盾、上半身が中心ですが、ドラゴンは長い首や尻尾のチェーン制御が重要になるため、専用 Component として分けています。

質問: IK でバグが起きたらどこを見ますか？
回答:
まず対象ボーン名が正しいかを確認します。
次に Animation の更新後に IK が適用されているか、目標位置や Raycast 結果が正しいか、補正量が大きすぎないかを見ます。
