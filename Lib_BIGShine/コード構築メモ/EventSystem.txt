EventSystem / ActionRegistry / Blackboard 説明メモ

最終編集日時
7/21

目的
このメモは、ゲーム内のイベント実行、Action 登録、Blackboard 連携、Animation / UI / Camera / Combat からの呼び出し関係を説明するためのもの。
イベントをコードに直書きするのではなく、名前付き Action とデータ駆動の Blackboard を組み合わせて、Editor から調整しやすい形にしている。


============================================================
1. 全体概要
============================================================

EventSystem は、ゲーム内の「何かが起きた時に何を呼ぶか」を名前で扱う仕組み。
中心になるのは次の要素。

- ActionRegistry
- IActionProvider
- ActionSequence
- BlackboardComponent
- GameObject の localRegistry
- 各 Component の RegisterActions

ActionRegistry は、Category と ActionName をキーにして std::function<void()> を登録する。
UIボタン、Animation Event、ActionSequence、CameraAction などは、登録された Action を名前で選び、実行する。

BlackboardComponent は、Action から直接引数を渡せない場合に、前段の処理が値を書き、後段の処理が読むための共有データ置き場として使う。
例えばジャストガードでは Guard / Position と Guard / Normal を書き、CameraActionDirectorComponent がそれを読んで注視点に使う。


============================================================
2. ActionRegistry
============================================================

場所
Code/Engine/GamePlay/Serialize/ActionRegistry.h
Code/Engine/GamePlay/Serialize/ActionRegistry.cpp

主な役割
- Category / ActionName / ActionFunc を登録する
- 登録済み Action を名前で検索する
- UIやEditorからCategory別にAction一覧を出せるようにする
- SceneBase 側でシーンごとの Registry を差し替えられるようにする

主なAPI
- RegisterAction
- GetCategories
- GetActionNames
- GetAction
- RemoveAction
- Call
- HasAction
- HasCategory
- HasActionInCategory
- Clear

登録形式
Category: CameraAction
Action: JustGuard

Category: CameraShake
Action: Heavy

Category: Camera
Action: LockOn_Toggle

注意点
現在の ActionFunc は std::function<void()> なので、基本的に引数付き Action は扱わない。
動的な値が必要な場合は、Blackboard に値を書いてから Action を呼ぶか、システム側から公開APIを直接呼ぶ。


============================================================
3. IActionProvider
============================================================

IActionProvider は、Component が自分の Action を登録できるようにするためのインターフェース。

代表例
- CameraDirector
- FovDirector
- CameraActionDirectorComponent
- CameraShakeComponent
- ParticleComponent
- AfterimageComponent
- UIButton から参照される Action 群

Component の Start や初期化時に RegisterActions を呼び、ActionRegistry に自分の機能を登録する。

利点
- 機能を持つ Component 自身が Action 名を管理できる
- Editor 側は ActionRegistry を見るだけで、呼べる Action を一覧化できる
- 新しい演出コンポーネントを追加しても、EventSystem 本体を大きく変更しなくてよい


============================================================
4. Global Action と Local Action
============================================================

Global Action
- ActionRegistry::Instance に登録される
- UI、Scene、Audio、Camera、PostProcess など、シーン全体から呼べる Action に使う
- RegisterAllActions や各 Component の RegisterActions から登録される

Local Action
- GameObject の localRegistry に登録される
- GameObject 固有の反応に使う
- BuildActionName と ExecuteAction を使い、対象オブジェクトや親階層に紐づいた Action を呼べる

Combat では Local Action が特に重要。
JustDodgeSystem は、ジャスト回避成功時に dodger 側または親階層の OnJustDodge を探して実行する。
GuardSystem は、ガード成功時に OnGuardSucceeded / OnJustGuardSucceeded を実行する。


============================================================
5. ActionSequence
============================================================

場所
Code/Engine/GamePlay/EventSystem/ActionSequence.h
Code/Engine/GamePlay/EventSystem/ActionSequence.cpp

主な役割
Action を時間順に実行するシーケンスコンポーネント。
イベントを複数並べ、遅延、実行タイミング、Blackboard 書き込みを Editor から管理できる。

使い方のイメージ
- 0.0秒: HitStop を開始
- 0.05秒: CameraShake / Heavy
- 0.08秒: Particle を再生
- 0.12秒: CameraAction / JustGuard
- 0.2秒: Blackboard のフラグを書き換え

ActionSequence は、ActionRegistry から Action を検索して実行する。
Action の前後で Blackboard Writes を行えるため、引数なし Action に対してもデータを渡すような使い方ができる。


============================================================
6. BlackboardComponent
============================================================

場所
Code/Engine/GamePlay/Core/Component/BlackboardComponent.h
Code/Engine/GamePlay/Core/Component/BlackboardComponent.cpp

主な役割
GameObject に紐づく共有データ領域。
Category と Key で値を管理する。

対応している型
- float
- int
- bool
- Vector2
- Vector3
- string
- Trigger

主なAPI
- SetFloat / GetFloat
- SetInt / GetInt
- SetBool / GetBool
- SetVector2 / GetVector2
- SetVector3 / GetVector3
- SetString / GetString
- SetTrigger / ConsumeTrigger
- HasValue
- ClearCategory

使われ方
- Animation の遷移条件
- Combat の結果通知
- Hit / Guard / Dodge の位置や法線
- GameMode の共有状態
- CameraAction の注視点指定

Blackboard は、ActionRegistry が引数なしであることの補完にもなっている。
例えば CameraAction / JustGuard は引数なし Action として登録されるが、実行時には CameraActionPreset の blackboardCategory / focusPositionKey を使って Guard / Position を読む。


============================================================
7. Combat との連携
============================================================

AttackSystem
- 攻撃ヒット時に Hit 情報を Blackboard へ書く。
- ダメージ、ヒット位置、ノックバック、エフェクトなどの反応につなげる。

JustDodgeSystem
- ジャスト回避成功時に Dodge / JustDodgeSucceeded、Dodge / JustDodgeTrigger、Dodge / Position、Dodge / Normal を書く。
- Local Action の OnJustDodge を探して呼ぶ。
- 今回、実カメラの CameraActionDirectorComponent を探して PlayActionAtPosition("JustDodge", position, normal) を呼ぶ導線を追加した。

GuardSystem
- 通常ガード成功時に Guard / GuardSucceeded を書く。
- ジャストガード成功時に Guard / JustGuardSucceeded、Guard / JustGuardTrigger、Guard / Position、Guard / Normal を書く。
- 通常ガードでは OnGuardSucceeded、ジャストガードでは OnJustGuardSucceeded を呼ぶ。
- 今回、ジャストガード時だけ PlayActionAtPosition("JustGuard", position, normal) を呼ぶ導線を追加した。

この構成により、戦闘判定、アニメーション反応、エフェクト、カメラ演出を疎結合にしている。


============================================================
8. CameraAction との連携
============================================================

CameraActionDirectorComponent は IActionProvider として、次のような Action を登録する。

Category: CameraAction
Action: JustGuard
Action: JustDodge

CameraShakeComponent は次の Action を登録する。

Category: CameraShake
Action: Light
Action: Heavy
Action: JustGuard

EventSystem から CameraAction / JustGuard を呼ぶ場合、CameraActionDirectorComponent は自分の preset に設定された Blackboard を読む。
直接呼び出しの場合は、JustDodgeSystem / GuardSystem から PlayActionAtPosition を呼ぶため、接触位置をそのまま使える。

引数なし Action と直接APIの使い分け

EventSystem
- 汎用的なイベント編集向け
- ActionSequence や UI から呼びやすい
- 動的な値は Blackboard 経由

直接API
- ジャスト回避やジャストガードのように、発生位置が毎回違う処理向け
- PlayActionAtPosition で接触位置や攻撃方向を直接渡せる
- EventSystem 本体を引数付きに作り替えずに済む


============================================================
9. Animation との連携
============================================================

AnimationControllerComponent は、AnimEvent や Sequencer から Action を呼べる。
攻撃アニメーションの特定フレームで、AttackTemplate、Particle、MeshVFX、CameraShake などを起動できる。

Animation 側のイベントでは、次のような使い方をする。

- startAction に CameraShake / Light を設定する
- endAction に Afterimage 停止を設定する
- blackboardWrites で HitStopDuration や EffectAssetPath を書く
- AnimationEnd や Trigger を使って状態遷移する

Animation と EventSystem を分けることで、アニメーション側は「何秒で何を呼ぶか」に集中し、各機能の具体的な処理は Component 側に持たせられる。


============================================================
10. UI との連携
============================================================

UIButton は ActionRegistry から選択された Action を取得し、クリック時に実行する。

使い道
- Scene 遷移
- Audio 再生
- Camera 切り替え
- Debug 用 Action
- Tutorial 用の演出開始

UI 側は具体的な処理を知らず、Action 名だけを保持する。
これにより、Button の見た目や配置と、実際の処理を分けている。

12. 設計上の注意点
============================================================

- ActionRegistry の Action は現在引数なしなので、動的な値は Blackboard か直接APIで扱う。
- RegisterActions が毎フレーム呼ばれると重複登録の原因になるため、Start や編集時に限定する。
- 同じ category / actionName の Action は RemoveAction してから再登録すると、プリセット名変更に対応しやすい。
- Lambda で Component をキャプチャする場合は、Scene 切り替え後に無効な参照が残らないように注意する。
- Local Action と Global Action の用途を混ぜすぎない。
- Combat 結果のように対象GameObjectが重要なものは Local Action、CameraShake のようにシーン全体から呼べるものは Global Action が向いている。
- Blackboard の category / key は文字列なので、typo で値が読めなくなる。重要なキーは定数化を検討する。


============================================================
13. 今回のカメラ演出追加での考え方
============================================================

今回、EventSystem 本体を引数付き Action に作り替えることはしていない。
理由は、既存の UI、Animation、ActionSequence が引数なし Action 前提で動いているため。

代わりに、次の2ルートを用意した。

1. EventSystem ルート
  CameraAction / JustGuard を呼ぶ。
  CameraActionDirectorComponent が Blackboard から Guard / Position を読む。

2. Combat 直接ルート
  JustDodgeSystem / GuardSystem が実カメラの CameraActionDirectorComponent を探し、PlayActionAtPosition を呼ぶ。
  接触位置や攻撃方向を直接渡せる。

この分け方により、Editor から呼べる汎用性と、ジャスト回避・ジャストガードの動的な演出精度を両立している。
