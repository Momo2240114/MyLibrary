Combatシステム関係 説明メモ

目的
このメモは、攻撃、当たり判定、ダメージ、ヒットリアクション、ジャスト回避、攻撃テンプレートを説明するための入口。
Animation Sequencer や Particle / MeshVFX とつながる、ゲームプレイ寄りの戦闘処理として整理する。

主な関連ファイル
- Code/Engine/GamePlay/Combat/AttackTemplateManager.h / .cpp
- Code/Engine/GamePlay/Combat/AttackTemplateRuntime.h / .cpp
- Code/Engine/GamePlay/Combat/AttackEffectHitComponent.h / .cpp
- Code/Engine/GamePlay/System/AttackSystem.h / .cpp
- Code/Engine/Physics/HitBox.h / .cpp
- Code/Engine/GamePlay/Combat/HealthComponent.h / .cpp
- Code/Engine/GamePlay/Combat/HitReactionComponent.h / .cpp
- Code/Engine/GamePlay/Combat/JustDodgeReactionComponent.h / .cpp
- Data/AttackTemplate/*.json

この機能を一言で説明するなら
攻撃データ、判定、ヒット時の処理、エフェクトを AttackTemplate と HitBox を中心にまとめた戦闘システム。

説明の中心
- AttackTemplate に攻撃の数値と演出をまとめる
- AttackTemplateRuntime が Sequencer のイベントに合わせて攻撃を開始、更新、終了する
- AttackSystem が攻撃インスタンスやヒット履歴を管理する
- HitBox が実際の当たり判定とヒット通知を行う
- HealthComponent がダメージを受ける
- HitReactionComponent が被弾時の反応を担当する
- JustDodgeReactionComponent がジャスト回避時の反応を担当する
- Particle / MeshVFX はヒット時や攻撃発生時の演出として呼ばれる

処理フロー
1. Animation Sequencer の攻撃イベントが開始する
2. AnimEvent の attackTemplateId から AttackTemplate を探す
3. AttackTemplateRuntime::Start で攻撃インスタンスを作る
4. HitBox に Damage、HitStop、KnockBack、HitEffect を設定する
5. イベント中に AttackTemplateRuntime::Update で判定や攻撃エフェクトを制御する
6. HitBox が対象に当たる
7. AttackSystem がヒット履歴を見て多段ヒットや重複ヒットを制御する
8. HealthComponent や HitReactionComponent に結果が反映される
9. ヒット位置に Particle / MeshVFX が出る
10. イベント終了時に AttackTemplateRuntime::End で HitBox を無効化する

詳しく書くときの見出し
1. Combat 全体の目的
2. AttackTemplate の設計
3. AttackTemplateRuntime の Start / Update / End
4. AttackSystem の役割
5. HitBox の役割
6. Health と HitReaction
7. JustDodge
8. Particle / MeshVFX との連携
9. JSON 保存と読み込み
10. 良い点と改善点

良い点
- 攻撃データを JSON 化して再利用できる
- アニメーション時間と攻撃判定を結びつけられる
- ヒット時エフェクトを攻撃テンプレート側で設定できる
- 武器判定とエフェクト判定の両方を扱える
- 多段ヒットやヒットグループを管理する入口がある

改善点
- AttackTemplate の項目が増えやすいので Editor の整理が重要
- HitBox 名や Asset 名の文字列参照は参照切れに注意が必要
- Debug 表示で攻撃インスタンス、HitBox、ヒット履歴を見えるようにすると検証しやすい


============================================================
1. Combat 全体概要
============================================================

Combat システムは、攻撃の発生、当たり判定、ダメージ、ヒットストップ、ノックバック、ヒットリアクション、ヒット時エフェクトをまとめて扱う仕組み。

このプロジェクトでは、攻撃の発生タイミングは Animation Sequencer が持ち、攻撃の中身は AttackTemplate が持つ。
実行時には AttackTemplateRuntime が AnimEvent と AttackTemplate をつなぎ、HitBox や EffectManager に必要な設定を渡す。

つまり Combat は単体で閉じているのではなく、Animation、Particle、MeshVFX、Physics、Health、PlayerState とつながる中間レイヤーになっている。

一言で説明するなら、
「アニメーションの時間イベントから、データ化された攻撃テンプレートを実行し、判定、ダメージ、ヒット演出までをまとめて処理する戦闘基盤」
と言える。


============================================================
2. この機能を作った理由
============================================================

解決したかった問題
- 攻撃ごとの数値をコードに書くと調整しづらい
- HitBox の有効時間をコードで管理するとアニメーションとズレやすい
- ヒット時 Particle や MeshVFX の設定が攻撃ごとに散らばりやすい
- 多段ヒット、ヒットストップ、ノックバックなどを毎回個別実装すると重複が増える
- 弱攻撃、強攻撃、空中攻撃などを増やしたとき、コード変更範囲が大きくなる

この設計で改善したこと
- AttackTemplate を JSON Asset 化し、攻撃ごとの調整をデータ側へ出した
- AttackTemplateRuntime により、Sequencer の Start / Update / End と攻撃処理を対応させた
- AttackSystem で攻撃インスタンスやヒット履歴を管理する入口を作った
- HitBox に攻撃データとヒットエフェクト情報を渡せるようにした
- AttackEffectHitComponent により、武器本体以外の攻撃エフェクトにも判定を持たせられるようにした


============================================================
3. 全体構成
============================================================

AttackTemplateManager
- 種類: Singleton Manager
- 主な責務:
  Data/AttackTemplate 以下の JSON を読み込み、AttackTemplate として管理する。
  Editor GUI で攻撃テンプレートを編集、保存する。
- 主な関数:
  LoadAll
  LoadTemplate
  SaveTemplate
  DuplicateTemplate
  FindTemplate
  DrawEditorGui
  DrawInlineEditor
  DrawEditorContent
- 説明のポイント:
  攻撃データの Asset 管理と Editor 編集を担当する。

AttackTemplate
- 種類: struct
- 主な責務:
  1つの攻撃に必要なデータをまとめる。
- 主なデータ:
  id
  displayName
  ownerTarget
  damage
  impactPower
  hitStopDuration
  hitStopScale
  knockBackPower
  targetAirLiftPower
  attackerAirLiftPower
  knockBackType
  hitGroupId
  allowMultiHit
  canHitOwner
  weaponHitBox
  hitEffect
  slashEffects
  attackEffects

AttackTemplateRuntime
- 種類: Runtime helper
- 主な責務:
  AnimEvent で指定された AttackTemplate を実行時に動かす。
- 主な関数:
  Start
  Update
  End
- 説明のポイント:
  Editor データである AttackTemplate を、実際の HitBox や VFX 生成に変換する役。

AttackSystem
- 種類: Manager / System
- 主な責務:
  攻撃インスタンスやヒット履歴を管理する。
- 説明のポイント:
  同じ攻撃が同じ対象へ何度も当たるのを防ぐ、多段ヒットを許可するなどの判断に使う。

HitBox
- 種類: Physics / Collider 系 Component
- 主な責務:
  実際の当たり判定、ヒット通知、ダメージ情報の保持。
- 説明のポイント:
  AttackTemplateRuntime からダメージやヒットストップなどを設定され、衝突時に対象へ結果を渡す。

AttackEffectHitComponent
- 種類: Component
- 主な責務:
  攻撃エフェクト側に付く当たり判定を管理する。
- 主なデータ:
  effectType
  ownerObject
  attackInstanceId
  hitGroupId
  damage
  impactPower
  hitStopDuration
  hitStopScale
  knockBackPower
  hitParticleAssetPath
  hitMeshVFXAssetPath
  lifeTime
  movementDirection
  movementSpeed
  hitShapes
- 説明のポイント:
  Projectile や範囲攻撃など、武器本体ではなく生成された攻撃オブジェクトに判定を持たせる。

HealthComponent
- 種類: Component
- 主な責務:
  HP やダメージ処理。
- 説明のポイント:
  HitBox からの攻撃結果を受け、体力を減らす側。

HitReactionComponent
- 種類: Component
- 主な責務:
  被弾時のリアクション。
- 説明のポイント:
  ダメージを受けた後の怯み、吹き飛び、アニメーション遷移などの入口として説明できる。

JustDodgeReactionComponent
- 種類: Component
- 主な責務:
  ジャスト回避時の特殊反応。
- 説明のポイント:
  通常ヒットとは別に、回避成功時の演出や時間制御などを扱うための入口。


============================================================
4. AttackTemplate の詳細
============================================================

AttackData
- damage:
  基本ダメージ。
- impactPower:
  ヒット時の衝撃量。
- hitStopDuration:
  ヒットストップの長さ。
- hitStopScale:
  ヒットストップ中の時間倍率。
- knockBackPower:
  ノックバックの強さ。
- targetAirLiftPower:
  相手を浮かせる力。
- attackerAirLiftPower:
  攻撃者側へかける浮き上がり量。
- knockBackType:
  どの方向へ吹き飛ばすか。
- hitGroupId:
  ヒット履歴のグループ分け。
- allowMultiHit:
  同じ攻撃で複数回ヒットできるか。

WeaponHitBox
- enabled:
  武器 HitBox を使うか。
- hitBoxName:
  対象 HitBox の名前。
- activeStartTime / activeEndTime:
  AttackTemplateRuntime::Update 内で有効化される時間。
- startNodeName / endNodeName:
  武器の根元と先端のノード名として使う想定のデータ。
- radius:
  武器判定の太さ。

HitEffect
- spawnOnHit:
  ヒット時にエフェクトを出すか。
- hitParticleAssetPath:
  ヒット時 Particle。
- hitParticleEmitterName:
  Particle 内の Emitter 名。
- hitParticleLifeTime:
  Particle の寿命。
- hitParticleNormalOffset:
  ヒット法線方向へのずらし量。
- hitMeshVfxAssetPath:
  ヒット時 MeshVFX。
- hitMeshVfxLifeTime:
  MeshVFX の寿命。
- hitMeshVfxNormalOffset:
  MeshVFX の位置ずらし量。

SlashEffect
- 攻撃開始時、または指定オフセットで出る斬撃 VFX。
- 見た目だけでなく hitBox を持てる。
- followOwner や followNode により、所有者やボーンへの追従に対応する入口がある。

AttackEffect
- Projectile、Area、Beam、Breath などの攻撃エフェクトを生成するためのテンプレート。
- Particle と MeshVFX のパスを持てる。
- hitShapes により、生成された攻撃エフェクト側に判定を持たせられる。


============================================================
5. 実行時の処理フロー
============================================================

攻撃開始
1. Animation Sequencer の AnimEvent が開始する
2. AnimEvent の eventTemplateType が ATTACK_TEMPLATE か確認する
3. attackTemplateId から AttackTemplateManager::FindTemplate でテンプレートを探す
4. AttackTemplateRuntime::Start を呼ぶ
5. AttackSystem から attackTemplateInstanceId を作る
6. event の runtime flag を有効化する
7. WeaponHitBox が有効なら HitBox を検索し、攻撃データを設定する
8. SlashEffect が有効なら EffectManager に SpawnSlashEffect を依頼する

攻撃中
1. AnimEvent の時間範囲内で AttackTemplateRuntime::Update が呼ばれる
2. WeaponHitBox の activeStartTime / activeEndTime を見て Activate / Deactivate する
3. AttackEffect の spawnTimeOffset を確認する
4. まだ生成していない AttackEffect を EffectManager から生成する
5. spawnedAttackEffects で二重生成を防ぐ

攻撃終了
1. AnimEvent が終了する
2. AttackTemplateRuntime::End を呼ぶ
3. WeaponHitBox を Deactivate する
4. HitBox の一時的な override を戻す
5. event の runtime flag を false に戻す
6. spawnedAttackEffects をクリアする

ヒット時
1. HitBox または AttackEffectHitComponent が対象と衝突する
2. AttackSystem がヒット履歴を確認する
3. HealthComponent にダメージを渡す
4. HitReactionComponent にリアクションを渡す
5. HitEffect の Particle / MeshVFX を VFXManager から生成する
6. 必要なら HitStop や KnockBack を適用する


============================================================
6. Serialize / Deserialize
============================================================

AttackTemplate JSON の主な構成
- AssetType
- AssetVersion
- id
- displayName
- owner
- attack
- weaponHitBox
- hitEffect
- slashEffects
- attackEffects

読み込み時の工夫
- Enum は文字列または int から読めるようになっている
- 一部の古いキー名も fallback として読んでいる
- Data/AttackTemplate 以下の JSON を LoadAll でまとめて読む

保存時の工夫
- SaveTemplate で JSON に整形して保存する
- ID を変更した場合、Animation や Scene 側にある attackTemplateId の参照を置換する処理がある
- SlashEffect や AttackEffect の配列もまとめて保存する

注意点
- 参照置換の対象外ファイルがあると古い ID が残る可能性がある
- Asset の移動や名前変更時は、Particle / MeshVFX のパス参照にも注意する
- 古い JSON 互換を保つ場合は、新規項目に必ずデフォルト値を用意する


============================================================
7. Editor GUI
============================================================

AttackTemplateManager Editor の主な編集項目
- Basic:
  ID、DisplayName、OwnerTarget、CanHitOwner。
- AttackData:
  Damage、ImpactPower、HitStop、KnockBack、AirLift、HitGroup、MultiHit。
- WeaponHitBox:
  有効化、HitBox 名、有効時間。
- HitEffect:
  Hit Particle、Hit MeshVFX、寿命、法線オフセット。
- SlashEffects:
  VFX Path、Spawn Offset、LifeTime、Transform、Follow、HitBox。
- AttackEffects:
  EffectType、Particle Path、MeshVFX Path、Transform、移動、HitShapes。

良い点
- 攻撃1つに必要な項目を Editor でまとめて見られる
- Particle / MeshVFX Asset を Combo から選べる
- SlashEffect と AttackEffect を複製、削除できる
- Save / Reload により JSON Asset として更新できる

改善点
- 項目が多いため、用途別プリセットがあると調整しやすい
- 攻撃再生 Preview があると、Animation と合わせた確認がしやすい
- HitBox の Debug 表示と連携すると説明しやすい
