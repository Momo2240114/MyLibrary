この機能を一言で説明するなら
描画済みの画面を RenderTarget と Shader で加工し、Bloom や Distortion などの画面効果をかける PostEffect システム。

説明の中心
- Scene を一度 RenderTarget に描画する
- PostRenderSystem が最終画面へ合成する
- BloomSystem が明るい部分を抽出、ぼかし、加算する
- PostDistortionSystem が歪み表現を行う
- MotionVelocityRenderSystem が速度情報を扱う

面接での短い説明
「PostEffect は、3D 描画結果を直接画面に出すのではなく、一度 RenderTarget に描いてから Shader で加工する仕組みです。
Bloom では明るい部分を抽出してぼかし、元の画面へ合成しています。
また Distortion や MotionVelocity など、画面全体に関わる効果を RenderSystem と Editor Window で調整できるようにしています。」

処理フロー
1. 通常の 3D / Sprite / VFX を RenderTarget に描画する
2. 必要に応じて輝度抽出や速度情報を作る
3. Bloom や Distortion などの PostEffect を適用する
4. 最終結果を BackBuffer に描画する
5. PostEffectWindow でパラメータを調整する

============================================================
1. PostEffect 全体概要
============================================================

PostEffect は、3D モデルや Sprite、Particle、MeshVFX を描画した後の画面に対して、さらに Shader で加工を行う仕組み。

通常の描画結果を直接 BackBuffer に出すのではなく、一度 RenderTarget に描画する。
その RenderTarget を ShaderResourceView として読み、Bloom、Distortion、MotionBlur、Vignette、GTAO などの効果を適用して最終画面へ出す。

このプロジェクトでは PostRenderSystem が中心になり、BloomSystem、PostDistortionSystem、MotionBlurSystem、VignetteSystem、XeGtaoSystem などを管理する。

一言で説明するなら、
「描画済みの画面を RenderTarget と Shader で加工し、Bloom や歪みなどを加える DirectX 11 の PostEffect システム」
と言える。


============================================================
2. この機能を作った理由
============================================================

解決したかった問題
- 発光表現や画面全体の演出をモデル単体の Shader だけで作るのは難しい
- Bloom や MotionBlur のような効果は、描画後の画面全体に対して処理する必要がある
- VFX や攻撃演出をより強く見せたい
- PostEffect の強さを Editor で調整したい
- RenderTarget を使った描画パイプラインを整理したい

この設計で改善したこと
- PostRenderSystem に画面後処理の入口をまとめた
- Bloom、Distortion、MotionBlur などを System 単位で分けた
- 作業用 RenderTarget を複数持ち、効果を順番に適用できるようにした
- PostEffectWindow から調整できる入口を作った
- Scene 描画と画面加工を分離した


============================================================
3. 全体構成
============================================================

PostRenderSystem
- 種類: RenderSystem
- 主な責務:
  PostEffect 全体の実行入口。
  sceneSRV を受け取り、各 PostEffect を適用して finalRTV へ出力する。
- 保持している重要データ:
  bloom
  radialBlur
  xeGtao
  motionBlur
  vignette
  postDistortion
  workBuffers
- 主な関数:
  Initialize
  Shutdown
  Execute
  CreatePostBuffer

PostBuffer
- 種類: 内部 struct
- 主な責務:
  PostEffect の作業用 RenderTarget。
- 保持している重要データ:
  texture
  rtv
  srv
- 説明のポイント:
  書き込み用 RTV と読み込み用 SRV の両方を持ち、Pass 間の受け渡しに使う。

BloomSystem
- 種類: PostEffect System
- 主な責務:
  明るい部分を抽出し、ぼかして元画像に加算する。
- 説明のポイント:
  発光感を出すための代表的な PostEffect。

PostDistortionSystem
- 種類: PostEffect System
- 主な責務:
  画面の歪み表現。
- 説明のポイント:
  爆発、熱気、魔法、衝撃波などで背景を歪ませる用途。

MotionBlurSystem
- 種類: PostEffect System
- 主な責務:
  速度情報を使ったブラー。
- 説明のポイント:
  カメラやオブジェクトの動きを強調する。

VignetteSystem
- 種類: PostEffect System
- 主な責務:
  画面端を暗くする効果。
- 説明のポイント:
  集中線的な演出、ダメージ時、雰囲気作りに使える。

XeGtaoSystem
- 種類: PostEffect / AO 系 System
- 主な責務:
  画面空間の Ambient Occlusion 系処理。
- 説明のポイント:
  接地感や奥行き感を強める画面効果として説明できる。

PostEffectWindow
- 種類: Editor Window
- 主な責務:
  PostEffect の有効化、強さ、各種パラメータを Editor から調整する。


============================================================
4. RenderTarget の基本フロー
============================================================

通常描画
1. Model、Sprite、Particle、MeshVFX などを Scene 用 RenderTarget に描画する
2. Scene 用 RenderTarget の SRV を作る
3. PostRenderSystem::Execute に sceneSRV と finalRTV を渡す

PostEffect 適用
1. sceneSRV を最初の入力にする
2. Bloom などの各 System が workBuffer に書き込む
3. 次の Pass は前の workBuffer の SRV を読む
4. 最後の結果を finalRTV に描画する

重要な考え方
- 同じ Texture に読み書きを同時にしない
- Pass ごとに RTV と SRV の役割を切り替える
- 画面サイズ変更時は RenderTarget を作り直す必要がある
- Shader に渡す ConstantBuffer と C++ 側の構造体を合わせる必要がある


============================================================
5. Bloom
============================================================

目的
- 明るい部分をにじませる
- 発光、魔法、エネルギー、斬撃 VFX を強く見せる
- 画面のリッチさを上げる

一般的な処理
1. 元画像から一定以上明るい部分を抽出する
2. 抽出画像を縮小する
3. 横方向、縦方向に Blur する
4. 元画像へ加算合成する
5. 強さや閾値を調整する

説明のポイント
「Bloom はモデル Shader だけではなく、画面全体の明るい部分を後から加工するための処理です。
VFX の発光 Texture や MeshVFX の emissive と組み合わせることで、攻撃演出を強く見せられます。」


============================================================
6. Distortion
============================================================

目的
- 背景や画面を歪ませて、熱気、衝撃波、魔法の揺らぎを表現する
- Particle や MeshVFX の見た目に画面全体の変化を加える

処理として説明できる流れ
1. Distortion 用の情報を別 Buffer に描画する
2. PostDistortionSystem が Scene 画像を読む
3. 歪み Texture や Vector に応じて UV をずらす
4. ずらした UV から Scene 画像を読み直す
5. final へ合成する

注意点
- 歪み量が大きすぎると画面が破綻する
- 画面端の UV Clamp / Border 処理が必要
- Distortion を Bloom の前にするか後にするかで見た目が変わる


============================================================
7. MotionBlur / Velocity
============================================================

目的
- 速い動きやカメラ移動を強調する
- アクションゲームのスピード感を上げる

必要な情報
- 現在フレームの位置
- 前フレームの位置
- 速度 Buffer
- Depth
- Camera 行列

説明のポイント
「MotionBlur は単純に画面をぼかすのではなく、速度情報を見てどちら方向にどれだけぼかすかを決める PostEffect です。
そのため MotionVelocityRenderSystem のように、速度情報を作る RenderSystem と組み合わせます。」

============================================================
9. 想定質問と回答例
============================================================

質問: PostEffect はなぜ RenderTarget を使うのですか？
回答:
画面全体を Shader で加工するには、一度描画結果を Texture として読む必要があるからです。
そのため Scene を RenderTarget に描き、その SRV を PostEffect Shader で読みます。

質問: Bloom の処理を説明してください。
回答:
まず元画像から明るい部分を抽出します。
次にその画像をぼかし、最後に元画像へ加算します。
これにより発光しているようなにじみを作れます。

質問: PostEffect のバグはどこを見ますか？
回答:
まず RenderTarget が正しく作られているか、RTV と SRV の切り替えが正しいかを見ます。
次に Shader に渡す Texture や ConstantBuffer が正しいか、Pass の順番が想定通りかを確認します。

質問: 効果の順番は重要ですか？
回答:
重要です。
Bloom、Distortion、MotionBlur の順番が変わると見た目も変わります。
そのため、PostRenderSystem 側で適用順を管理する必要があります。
