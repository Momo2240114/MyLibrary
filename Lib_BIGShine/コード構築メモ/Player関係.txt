Player関係 説明メモ

目的
このメモは、PlayerController、PlayerStateMachine、各 PlayerState、PlayerStateEditorWindow を説明するための入口。
入力から状態が変わり、移動、攻撃、回避、被弾へつながる流れとして整理する。

この機能を一言で説明するなら
プレイヤーの入力、移動、攻撃、回避、被弾を StateMachine で分けて管理する Player 制御システム。

説明の中心
- PlayerControllerComponent が入力や各 Component への橋渡しを行う
- PlayerStateMachine が現在の状態を管理する
- PlayerState が各状態の共通インターフェースになる
- Idle / Move / Jump / Attack / Dodge / Hit などを個別 State として分ける
- PlayerAttackState は Animation Sequencer や AttackTemplate とつながる
- PlayerStateEditorWindow で状態や遷移を確認、調整する

処理フロー
1. PlayerControllerComponent が入力や現在状況を読む
2. PlayerStateMachine が現在 State を Update する
3. State 内で移動、ジャンプ、攻撃、回避などの処理を行う
4. 条件に応じて別 State へ遷移する
5. 攻撃 State では Animation / Combat 側へ処理がつながる
6. 被弾時は HitState や Combat の HitReaction と連携する

10. 良い点と改善点

良い点
- 状態ごとに処理を分けているため見通しがよい
- 攻撃、回避、被弾などを個別に拡張しやすい
- Animation / Combat と連携しやすい入口がある
- Editor で状態確認できる構成になっている

改善点
- State 間の遷移条件を一覧化すると説明しやすい
- AnimationController 側のノードグラフとの役割分担を明確にするとよい
- 入力、移動、攻撃予約、キャンセルなどは表にすると企業説明で伝わりやすい


============================================================
1. Player 全体概要
============================================================

Player システムは、プレイヤーの入力、移動、ジャンプ、攻撃、回避、被弾などを StateMachine で分けて管理する仕組み。

PlayerControllerComponent がプレイヤー制御の入口になり、PlayerStateMachine が現在の状態を持つ。
各状態は PlayerState を継承した Idle、Move、Jump、Attack、Dodge、Hit などのクラスに分かれる。

この構成の狙いは、プレイヤー処理を1つの巨大な Update にまとめず、状態ごとの責務へ分けること。
攻撃処理は Combat や Animation Sequencer とつながり、回避処理は JustDodge、被弾処理は HitReaction と連携する。

一言で説明するなら、
「プレイヤーの行動を State ごとに分け、入力から移動、攻撃、回避、被弾までを拡張しやすくした Player 制御システム」
と言える。


============================================================
2. この機能を作った理由
============================================================

解決したかった問題
- 入力処理、移動処理、攻撃処理を1つの Update に書くと複雑になる
- 攻撃中、回避中、被弾中などで入力の扱いが変わる
- 状態ごとの Enter / Update / Exit を分けないと、初期化や後片付けが散らばる
- 攻撃キャンセル、回避キャンセル、着地などを追加すると if 文が増えやすい
- Animation や Combat とつながる処理を整理したい

この設計で改善したこと
- PlayerStateMachine で現在状態を一元管理した
- 各 PlayerState に状態ごとの処理を閉じ込めた
- PlayerControllerComponent を入力や共通 Component への窓口にした
- AttackState から Animation / Combat へつなげやすくした
- DodgeState、HitState などを分け、特殊行動を拡張しやすくした


============================================================
3. 全体構成
============================================================

PlayerControllerComponent
- 種類: Component
- 主な責務:
  プレイヤー操作の入口。入力、移動 Component、Animation、Combat、Camera などとの橋渡しを行う。
- 説明のポイント:
  直接すべての行動を処理するのではなく、StateMachine を通して現在状態に処理を任せる。

PlayerStateMachine
- 種類: State 管理クラス
- 主な責務:
  PLAYER_ACTION と PlayerState を対応付け、現在状態を更新、切り替えする。
- 保持している重要データ:
  states
  owner
  playerController
  currentState
  currentAction
- 主な関数:
  Initialize
  AddState
  ChangeState
  Update
  GetCurrentStateName
  GetCurrentAction

PlayerState
- 種類: 基底クラス
- 主な責務:
  各 Player 状態の共通インターフェース。
- 説明のポイント:
  Idle、Move、Jump、Attack などが共通の形で扱われる。

PlayerIdleState
- 主な責務:
  入力がない待機状態。
- 説明のポイント:
  移動入力が入ったら Move、攻撃入力が入ったら Attack へ遷移する入口。

PlayerMoveState
- 主な責務:
  地上移動。
- 説明のポイント:
  CharacterMovementComponent などを使い、入力方向へ移動する。

PlayerJumpState
- 主な責務:
  ジャンプ、空中制御、着地。
- 説明のポイント:
  地上状態と空中状態で入力や攻撃の扱いが変わるため、分けて管理する。

PlayerAttackState
- 主な責務:
  攻撃中の入力、コンボ、Animation / Combat 連携。
- 説明のポイント:
  攻撃アニメーション、AttackTemplate、Sequencer イベントとつながる重要な状態。

PlayerDodgeState
- 主な責務:
  回避処理。
- 説明のポイント:
  無敵時間、移動、ジャスト回避判定などと連携する入口。

PlayerHitState
- 主な責務:
  被弾中の処理。
- 説明のポイント:
  HitReactionComponent や Animation 遷移と連携する。

PlayerActionState
- 主な責務:
  汎用的な行動状態。
- 説明のポイント:
  特殊アクションや共通行動の土台として説明できる。

PlayerStateEditorWindow
- 種類: Editor Window
- 主な責務:
  Player State の状態やパラメータ確認、調整。


============================================================
4. StateMachine の処理フロー
============================================================

初期化
1. PlayerControllerComponent が Start される
2. PlayerStateMachine::Initialize が呼ばれる
3. owner と playerController を保持する
4. AddState で Idle、Move、Jump、Attack、Dodge、Hit などを登録する
5. 初期 State に ChangeState する

毎フレーム
1. PlayerControllerComponent::Update が呼ばれる
2. 入力や現在状況を読む
3. PlayerStateMachine::Update が呼ばれる
4. currentState の Update が呼ばれる
5. State 内で移動、攻撃、回避、遷移判定を行う
6. 条件が成立すれば ChangeState する

状態遷移
1. ChangeState に PLAYER_ACTION を渡す
2. 現在 State の Exit 処理を行う想定
3. currentAction と currentState を更新する
4. 次 State の Enter 処理を行う想定
5. 次フレームから新しい State の Update が動く

説明時の注意
コード上で Enter / Exit の名前が実際にどう定義されているかは PlayerState 側を確認して話す。
説明時は「状態ごとに初期化、更新、終了を分けられる設計」と表現すると安全。


============================================================
5. Player と Animation の関係
============================================================

Player の StateMachine と AnimationController の NodeGraph は役割が違う。

PlayerStateMachine
- 入力やゲームプレイ上の行動状態を管理する
- 例:
  移動中、攻撃中、回避中、被弾中

AnimationController NodeGraph
- アニメーションの再生状態とブレンド、遷移を管理する
- 例:
  Idle animation、Run animation、Attack animation、Hit animation

関係
- PlayerAttackState が攻撃開始を決める
- AnimationController が攻撃アニメーションを再生する
- Animation Sequencer が攻撃判定や VFX のタイミングを出す
- Combat が実際の判定、ダメージ、ヒット処理を行う

説明例
「PlayerStateMachine はゲームプレイの状態、AnimationController は見た目のアニメーション状態を扱っています。
攻撃開始は PlayerState 側で判断し、攻撃中の細かい判定タイミングは Animation Sequencer 側で管理しています。」


============================================================
6. Player と Combat の関係
============================================================

攻撃時
1. 入力で PlayerAttackState へ遷移する
2. PlayerAttackState が攻撃アニメーションや攻撃状態を開始する
3. Animation Sequencer の AnimEvent が AttackTemplate を実行する
4. HitBox や AttackEffect が有効になる
5. 対象に当たると Combat 側で Damage、HitStop、KnockBack が処理される

回避時
1. 入力で PlayerDodgeState へ遷移する
2. 回避中の時間や移動を処理する
3. JustDodgeReactionComponent と連携し、攻撃をギリギリで避けた場合の反応を扱う

被弾時
1. HitBox からダメージやリアクション情報を受ける
2. HitReactionComponent が反応を決める
3. PlayerHitState へ遷移する
4. AnimationController が被弾アニメーションへ遷移する


============================================================
7. Editor / Debug
============================================================

PlayerStateEditorWindow で説明できること
- 現在の Player State を確認する
- 状態切り替えやパラメータ確認を行う
- Debug 用に Player の状態を見えるようにする

Debug で見るとよい値
- currentAction
- currentStateName
- 移動入力
- 地上判定
- 攻撃中か
- 回避中か
- 被弾中か
- 現在アニメーション State
- AttackTemplateId
