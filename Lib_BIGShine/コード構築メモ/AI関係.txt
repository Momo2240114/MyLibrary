敵キャラクターの行動をコード固定ではなく、条件とノード構造で管理する仕組みとして整理する。

この機能を一言で説明するなら
敵の行動判断を BehaviorGraph と Blackboard で管理し、Editor から行動の流れを調整できるようにした AI 制御システム。

説明の中心
- AIControllerComponent が敵 AI の実行入口になる
- AIBehaviorGraph が行動ノードや条件を持つ
- Blackboard が距離、状態、攻撃可能かどうかなどの判断材料を共有する
- AIActionComponent が具体的な行動を実行する
- AIBehaviorEditorWindow で行動グラフを編集する
- AIDirector は複数 AI や戦闘全体の調整役として説明できる
- DragonAI はボスや特殊敵用の専用 AI として説明できる

良い点
- 行動条件を Blackboard に集約できる
- 敵ごとの行動を BehaviorGraph Asset として分けられる
- Editor で行動の構造を見ながら調整できる

- 文字列キーの Blackboard は参照ミスに注意が必要
- Debug 表示で「なぜその行動を選んだか」を見えるようにすると説明しやすい


============================================================
1. AI 全体概要
============================================================

この AI 実装は、敵の行動を「コード内の巨大な if 文,switch文」ではなく、BehaviorGraph と Blackboard に分けて管理するための仕組み。

AIControllerComponent が実行入口になり、毎フレーム AIBehaviorContext を更新して AIBehaviorGraph を Tick する。
AIBehaviorGraph は、Root、Selector、Sequence、Condition、Action、Wait などのノードを持ち、現在の Blackboard 値を見ながら次に実行する行動を決める。

行動そのものは ActionRegistry に登録された Action 名で呼び出す。
これにより、AI の判断ロジックと実際の移動、攻撃、待機などの処理を分けて説明できる。

この構成の狙い
- 敵ごとの行動パターンを JSON Asset として分ける
- 行動条件を Blackboard に集約する
- Editor で BehaviorGraph を見ながら調整できる
- AI の判断処理と実際の移動、攻撃処理を分離する
- 通常敵、ボス、ディレクター制御へ拡張しやすくする


============================================================
2. この機能を作った理由
============================================================

解決したかった問題
- 敵 AI の分岐をコードだけで書くと、行動が増えたときに読みにくくなる
- 敵ごとに似たような if 文が増えると、修正漏れが起きやすい
- 「なぜその行動を選んだか」がコードを読まないと分からない
- 距離、ターゲット有無、攻撃可能かどうかなどの判断材料が散らばりやすい
- チーム制作で敵の行動を調整するたびにプログラマー作業が必要になる

この設計で改善したこと
- BehaviorGraph により、行動の流れをノードとして見えるようにした
- Blackboard により、AI 判断に使う値を共有しやすくした
- ActionRegistry により、グラフから実処理を名前で呼べるようにした
- JSON 保存により、敵ごとの行動データを外部化した
- AIControllerComponent と AIBehaviorGraph を分け、Component と Graph の責務を分離した


============================================================
3. 全体構成
============================================================

AIControllerComponent
- 種類: Component
- 主な責務:
  AI の実行入口。ターゲット探索、距離計算、Blackboard 書き込み、BehaviorGraph の Tick、デフォルト Action 登録を担当する。
- 保持している重要データ:
  graph
  context
  blackboardComponent
  graphAssetPath
  targetName
  spawnPosition
  detectRange
  attackRange
  lostRange
  chaseSpeed
  returnSpeed
  isRunning
- 呼び出されるタイミング:
  Start で初期化、Update で毎フレーム AI を進める。

AIBehaviorGraph
- 種類: Graph 実行クラス
- 主な責務:
  AIBehaviorNode と AIBehaviorLink を保持し、Root からノードを評価する。
- 保持している重要データ:
  nodes
  links
  runtimeStates
  nextId
- 主な関数:
  Tick
  ResetRuntime
  AddNode
  RemoveNode
  AddLink
  RemoveLink
  Serialize
  Deserialize
  SaveToFile
  LoadFromFile

AIBehaviorNode
- 種類: struct
- 主な責務:
  BehaviorGraph 上の1つのノードを表す。
- 保持している重要データ:
  id
  inputPinId
  outputPinId
  type
  name
  scopeId
  position
  blackboardCategory
  blackboardKey
  compareType
  valueType
  actionName
  waitForActionEnd
  waitSeconds
  subGraphName
  priority
  weight

AIBehaviorLink
- 種類: struct
- 主な責務:
  ノード同士の接続を表す。
- 保持している重要データ:
  id
  fromNodeId
  toNodeId
  fromPinId
  toPinId

AIBehaviorContext
- 種類: struct
- 主な責務:
  AI の Tick 中に使う現在状況をまとめる。
- 保持している重要データ:
  owner
  target
  blackboard
  globalBlackboard
  ownerPosition
  targetPosition
  spawnPosition
  toTargetDirection
  toSpawnDirection
  targetDistance
  spawnDistance
  deltaTime
  hasTarget

AIActionComponent
- 種類: Component
- 主な責務:
  AI から呼ばれる Action をまとめる入口として使う。
- 説明の仕方:
  BehaviorGraph は行動を決める側で、AIActionComponent や Controller 側の Action が実際の移動、攻撃などを行う。

AIBehaviorEditorWindow
- 種類: Editor Window
- 主な責務:
  AIBehaviorGraph のノード、リンク、条件、Action 名などを Editor 上で編集する。

AIDirectorComponent
- 種類: Game 側 Component
- 主な責務:
  複数 AI や戦闘全体の流れを管理するための上位制御。
- 説明の仕方:
  個別 AI が「自分の行動」を決めるのに対して、Director は戦闘全体の圧や状況を見て調整する役割。

DragonAIComponent
- 種類: Game 側 Component
- 主な責務:
  ドラゴンのような通常敵と異なる専用行動を扱う。
- 説明の仕方:
  汎用 BehaviorGraph で足りないボス固有処理を専用 Component として分けている。


============================================================
4. BehaviorGraph のノード種別
============================================================

ROOT
- グラフの開始地点。
- Tick は Root から子ノードへ流れる。

SELECTOR
- 子ノードを順番に試し、成功したものを採用する。
- 例:
  攻撃できるなら攻撃、できなければ追跡、ターゲットがなければ待機。

SEQUENCE
- 子ノードを順番に実行し、途中で失敗したら全体も失敗する。
- 例:
  ターゲットがいるか確認し、距離が近いか確認し、攻撃 Action を実行する。

RANDOM_SELECTOR
- 複数の候補からランダムに選ぶ用途。
- 同じ行動ばかりにならないようにするために使える。

BLACKBOARD_CONDITION
- Blackboard の値を比較して成功、失敗を返す。
- 例:
  TargetDistance < AttackRange
  HasTarget == true
  IsActionEnded == true

SET_BLACKBOARD
- Blackboard に値を書き込む。
- 行動開始フラグや状態フラグの設定に使える。

PLAY_ACTION
- ActionRegistry に登録された Action を呼ぶ。
- 実際の移動、攻撃、停止などはここから呼び出す。

WAIT
- 指定秒数待つ。
- 行動後の硬直や間を作るために使える。

WAIT_BLACKBOARD_BOOL
- Blackboard の bool が指定状態になるまで待つ用途。
- Action の終了待ちなどに使える。

SUB_GRAPH
- 行動グラフを階層化するためのノード。
- 複雑な敵行動をまとまりごとに分けるために使える。


============================================================
5. Blackboard の役割
============================================================

Blackboard は、AI の判断材料や一時状態を入れる共有データ。
AIBehaviorGraph の条件ノードは Blackboard の値を見て成功、失敗を判定する。

入る可能性のある値
- ターゲットがいるか
- ターゲットまでの距離
- スポーン位置からの距離
- 攻撃範囲内か
- 検知範囲内か
- 行動が終了したか
- 現在の AI 状態
- Debug 用の値

Local と Global
- LOCAL:
  その GameObject の Blackboard。
- GLOBAL:
  複数 AI や Director と共有する Blackboard。

設計上の良い点
- AI の条件判定と実処理を疎結合にできる
- Editor から条件を変更しやすい
- Debug 表示で AI の判断材料を確認しやすい

注意点
- 文字列キーなのでタイプミスに注意が必要
- キーが増えると整理が必要
- どの Component が書いて、どの Graph が読むかをメモに残すとよい


============================================================
6. 実行時の処理フロー
============================================================

初期化
1. AIControllerComponent が Start される
2. BlackboardComponent を確保する
3. graphAssetPath から BehaviorGraph を読み込む
4. spawnPosition を記録する
5. デフォルト AI Action を ActionRegistry に登録する
6. Graph の Runtime 状態を Reset する

毎フレーム
1. AIControllerComponent::Update が呼ばれる
2. isRunning が false なら何もしない
3. ResolveTarget で targetName の GameObject を探す
4. ownerPosition、targetPosition、targetDistance などを AIBehaviorContext に入れる
5. WriteContextBlackboard で Blackboard に現在状況を書く
6. AIBehaviorGraph::Tick に context を渡す
7. Root からノードが評価される
8. Condition が Blackboard を見て成功、失敗を返す
9. PlayAction が必要な Action を呼ぶ
10. Action の実行結果や終了フラグに応じて次の Tick が変わる

停止とリセット
- Stop で AI の実行を止める
- Play で再開する
- ResetTree で Graph の Runtime 状態を初期化する
